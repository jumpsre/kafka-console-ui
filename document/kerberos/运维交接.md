# Kerberos 集成 — 运维交接清单

针对本次 Kerberos(GSSAPI) 集成上线的运维须知。

## 一、上线前置检查

| 项 | 校验方法 | 不通过的影响 |
|---|---|---|
| JDK | `java -version` ≥ 1.8 | 无法启动 |
| 控制台机器到 KDC 88/UDP+TCP 可达 | `nc -vz <kdc> 88` | TGT 获取失败 |
| 控制台机器到 broker 9092（或 SASL 端口）可达 | `nc -vz <broker> 9092` | metadata 拉不到 |
| 控制台机器与 KDC、broker 时间偏差 ≤ 5 分钟 | `chronyc tracking` 或 `ntpstat` | `Pre-authentication failed (24)` |
| broker 主机名正反向解析互通 | `dig <broker>` + `dig -x <broker_ip>` | `Server not found in Kerberos database (7)` |
| keytab 与 principal 匹配 | `kinit -kt xxx.keytab <principal>` 在控制台机器上手验 | 控制台测试连接失败 |

## 二、首次上线步骤

```bash
# 1. 解压发布包
unzip kafka-console-ui-1.x.x.zip
cd kafka-console-ui-1.x.x

# 2. 配置 krb5.conf（多 realm 共存写在同一份）
cp config/krb5.conf.template config/krb5.conf
vi config/krb5.conf
#   - default_realm 改为业务默认 realm
#   - [realms] 段填全部 KDC 主机
#   - [domain_realm] 段把域名映射到 realm

# 3. 启动
sh bin/start.sh
# 启动日志若包含 "Found krb5.conf, enable Kerberos: ..." 表明已自动注入

# 4. 浏览器打开 http://<服务器>:7766
#    运维 → 集群切换 → 新增集群 → 认证方式选 SASL_PLAINTEXT/SSL + Kerberos(GSSAPI)
#    上传 keytab、填 principal、点"测试连接"
#    成功后提交保存，切换到该集群即可
```

## 三、需要监控的目录与文件

| 路径 | 用途 | 备份要求 |
|---|---|---|
| `${data.dir}/data/db/kafka-console.*` | H2 数据库（集群配置、用户、ACL 用户） | 高（含 keytab fileId 引用） |
| `${data.dir}/data/keytab/*.keytab` | 上传的 keytab 文件，权限 600 | 高（丢失需重新上传） |
| `${data.dir}/data/keytab/*.meta` | keytab 原始文件名 metadata | 低 |
| `config/krb5.conf` | KDC 配置 | 中（KDC 信息变更需同步） |
| `kafka-console-ui.log` | 应用日志（已脱敏，不含 jaas.config / password） | 按公司日志策略 |

## 四、已知风险与边界

### 4.1 JVM 全局 krb5.conf
`java.security.krb5.conf` 是 JVM 启动参数，**整个进程只有一份**。多个 Kerberos 集群必须**共用一份** `krb5.conf`，通过其内部 `[realms]` + `[domain_realm]` 多 realm 配置区分。

修改 `krb5.conf` 后**必须重启** Java 进程才能生效。控制台 UI 上没有热加载入口（即使将来有，也不能可靠刷新已 cache 的 Subject）。

### 4.2 keytab 文件管理
- keytab 落盘在 `${data.dir}/data/keytab/<UUID>.keytab`，POSIX 系统下权限被设为 600
- **控制台不提供 keytab 下载** —— 防止外泄
- 删除 keytab 前会扫所有集群 `properties` 字段，被引用则拒绝删除
- KDC 侧 KVNO 升版后，旧 keytab 失效；这时需要在控制台**重新上传 keytab 并替换集群配置中的引用**

### 4.3 集群编辑无并发锁
两个用户同时编辑同一集群可能后写覆盖前写。运维场景并发罕见，未做特殊保护。变更敏感配置时建议**约定单人操作**。

### 4.4 AdminClient 连接缓存
默认 `kafka.config.cache-admin-connection: true`。修改集群属性后，旧 AdminClient 仍在缓存中可能继续工作直到 TTL 过期（缓存类是 `TimeBasedCache`）。

**建议**：修改 Kerberos 关键字段（principal/keytab/krb5.conf）后，**重启进程**最稳。或等待 TTL 自然过期。

### 4.5 ACL 用户管理在 Kerberos 集群下不可用
- `T_KAFKA_USER` 表只服务于 SASL_SCRAM
- Kerberos 集群下 SaslScram 页面"新增/更新用户"按钮置灰，提示"principal 由 KDC 管理"
- 后端三处用户 CRUD 接口在 GSSAPI 机制下返回明确错误
- ACL 授权（producer/consumer/clear/delete）对 Kerberos 集群完全可用

### 4.6 审计日志已脱敏
`ControllerLogAspect` 在写日志前调 `SensitiveLogMasker.mask()`，遮蔽：
- `sasl.jaas.config` 整段值（包括其中的 keytab 路径与 principal）
- 任何包含 `password` 的 key/value
- JAAS 内嵌 `password="..."`（SCRAM 场景）

**注意**：脱敏只覆盖 `@ControllerLog` 注解的接口。如有自定义日志输出（如直接调 `log.info(props)`），请确保不要打印未脱敏的 properties。

## 五、常见报错对照（运维快速定位）

| 报错 | 触发位置 | 立即排查 |
|---|---|---|
| `Cannot locate default realm` | 任何 admin 操作 | `config/krb5.conf` 是否存在；启动日志有无 "Found krb5.conf" |
| `Pre-authentication information was invalid (24)` | 测试连接 | keytab 与 principal 是否匹配（`klist -k -t xxx.keytab` 看 KVNO） |
| `GSS initiate failed [...] No valid credentials provided` | 测试连接 | 时间偏差、KDC 可达性、SPN 配置 |
| `LoginException: Unable to obtain password from user` | 启动后第一次 admin 调用 | keytab 文件权限、路径错误（看脱敏前的本地日志） |
| `Server not found in Kerberos database (7)` | 测试连接 | broker 主机名正反向解析；`[domain_realm]` 映射 |
| `Authentication failed` | 任何操作 | broker 端 ACL 是否给该 principal 授权 |

### 打开 Kerberos 调试日志（仅排错时）

```bash
# 编辑 bin/start.sh
# 把 -Dsun.security.krb5.debug=false 改为 true
# 重启
# 查看 kafka-console-ui.log 里的 Kerberos 协商详细过程
# 排错完成后**改回 false**——debug 日志会泄露部分 Kerberos 元信息
```

## 六、回滚方案

若 Kerberos 集成出现严重问题需要降级：

1. **集群切换层面回滚**：UI 上把集群"认证方式"改回 `SASL_PLAINTEXT + SCRAM` 或"无"，不需要重启
2. **进程层面回滚**：停服 → 替换为 Kerberos 集成前的旧版本 jar → 启动；H2 中已配置过 Kerberos 的集群会**无法连接**（因为属性里有 GSSAPI 配置但旧版不支持），需手动从 H2 控制台或 SQL 工具删除这些集群记录
3. **数据完整性**：Kerberos 集成不修改 `T_KAFKA_USER`、`T_MIN_OFFSET_ALIGNMENT`、`t_sys_user/role/permission` 等存量表的语义；只对 `T_CLUSTER_INFO.PROPERTIES` 列做了**字段长度扩容**（1024 → 4096），向下兼容老数据

## 七、联系与升级路径

- 应用日志位置：项目根目录 `kafka-console-ui.log`、错误输出 `error.out`
- H2 控制台：`http://<服务器>:7766/h2-console`（`spring.h2.console.enabled: true`）—— 紧急排查时可登入查 `T_CLUSTER_INFO.PROPERTIES`，但记得别把脱敏前的 jaas 截图
- 升级新版本：保留 `data/`、`config/krb5.conf`、`config/application.yml`，替换 `lib/` 与 `bin/`
